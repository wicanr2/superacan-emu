# UMC6619 聲音執行模型

本文件記錄目前可由測試回查的 UMC6619 實作契約。這是晶片模擬工作，並非把
音效事件改寫成高階播放 API；W65C02、聲音 RAM、間接暫存器、計時器、DMA 與
PCM 取樣都保留為機器內可觀察的狀態。

## 已實作契約

- UMC6619 與 W65C02 共用 3,579,545 Hz 時脈，每 80 個聲音時脈產生一個立體聲
  樣本，名義取樣率為 44,744.3125 Hz。
- 16 個 PCM 聲道由 64 KiB 聲音 RAM 讀取無號 8 位元樣本，再轉成有號訊號混音。
- `$20-$2f`／`$30-$3f` 設定音高；累加量為 `pitch << 6` 的 16.16 定點值。
- `$50-$5f` 設定長度及單次播放；`$60-$6f`／`$70-$7f` 設定以 64 位元組為單位
  的起始位置；`$e0-$ef` 設定左右音量。
- `$17` 的低半位元組選擇聲道，高半位元組控制啟動或停止。這刻意修正封存
  C++ 程式把暫存器編號誤當聲道編號、固定操作聲道 7 的錯誤。
- 計時器週期為 `10 * (0x10000 - timerValue)`；啟用 IRQ 時以 `$80` 維持電位，
  讀取 `$14` 才確認並清除。
- DMA 完成 IRQ 使用 `$40` 維持電位；讀取 `$16` 確認並清除，回傳值的 bit 6
  同時反映 DMA 聲道是否仍忙碌。
- 音訊 IRQ 在每個 W65C02 指令邊界取樣。W65C02 已實作七週期 IRQ 入口、`RTI`
  與 `WAI` 喚醒語意；進入 IRQ 時設定 I、清除 D，並保留電位觸發行為。

## 驗證狀態

單元測試涵蓋間接暫存器、聲道選擇、PCM 定點步進、單次播放、計時器 IRQ、
DMA IRQ、IRQ／RTI 堆疊與 `WAI` 喚醒。Boom Zoo 的 120 幀真實 ROM 回歸可完成，
聲音 CPU 執行 2,129,677 個指令、產生 82,158 個樣本，計時器 IRQ 可進入 handler
並清除後返回 `$F07D`。該段啟動畫面沒有啟動 PCM 聲道，因此樣本仍全為零；這只
證明時脈與 IRQ 路徑，不應宣稱實際遊戲音訊已完成驗收。

## 尚待證實

- 需要以會實際觸發音樂或音效的正常玩家路徑，驗證非零 PCM、聲道循環、DMA
  補充資料與左右聲道輸出。
- 混音的半幅裕量及飽和方式目前沿用既有硬體研究模型，尚無類比輸出實測證據。
- 間接埠 busy bit 目前為立即完成；若 ROM 或實機證據顯示延遲，必須回到時序規格
  補建狀態，不可在前端加入等待補丁。
